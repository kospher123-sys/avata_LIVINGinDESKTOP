# 검수된 에셋 ZIP 납품 및 다음 Work 채팅용 인계 프롬프트 표준

> 적용 범위: Avatar Living in Desktop의 캐릭터 모션, 이펙트, 합성 애니메이션 및 기타 이미지 에셋 제작·검수 작업
> 결정: 2026-11-11 사용자 요청

## 핵심 의무

**이미지 생성·검수·수정을 끝내고 결과 ZIP을 납품하는 모든 작업은, 최종 답변에서 ZIP 소개와 다음 Work 채팅에 그대로 붙여 넣을 수 있는 `인계/구현 프롬프트`를 반드시 함께 제공한다.**

- 사용자는 기획/이미지 생성 채팅에서 결과를 받은 뒤 별도의 Work 채팅에 ZIP을 첨부하여 실제 프로그램에 적용한다.
- ZIP만 주거나 `작업 완료`만 말하지 않는다. 인계 프롬프트가 있어야 납품 완료다.
- **GitHub 문서가 그 자체로 모든 새 채팅에 자동 실행되는 것은 아니다.** 해당 작업을 맡은 Work에 이 문서를 읽고 준수하도록 지시하고, 각 납품 단계에서 프롬프트를 명시적으로 출력하게 한다.
- 원본 ZIP과 적용용 결과물의 위치·용도·검증 수준을 구분한다. 실제 파일을 확인하지 않은 내용(경로, 크기, 프레임 수, PASS)은 절대 확정 기재하지 않는다.
- 프로그램/에셋/문서는 사용자가 지정한 작업 범위에 따라서만 수정한다. 사용자 실기기 확인과 자동 검사를 별도로 기록한다.

## 작업 종료 시 필수 산출물

1. **ZIP 링크 및 내용 소개**: 실제 생성·확인된 ZIP 정확한 이름/경로, 어떤 기술/동작용인지, 포함된 에셋(카테고리·실제 프레임 수), 최종 적용용 폴더와 보관/검수용 폴더를 구분한다.
2. **검수 결과 요약**: 실제 검사한 파일 형식·RGBA/알파·프레임 수·캔버스·앵커·프린지·루프/구간 전환·밝고 어두운 배경 가독성·실제 재생 여부. `PASS / WARNING / FAIL / 미검증`을 명시한다.
3. **적용 주의사항**: 기준 손바닥 좌표, 바닥 기준점, 방향 반전, 권장 프레임 시간, 합성 순서, 구간 동기화 등 실제 확인된 값. 확인 불가능한 사항은 `Work가 분석 후 결정`이라고 적는다.
4. **다음 Work 채팅에 복사할 인계 프롬프트**: 아래 필수 형식을 채운 완결된 한국어 지시문을 제공한다.
5. **GitHub 반영 정보**: 해당 작업이 검수 완료되어 GitHub 업데이트 대상이면 실제 커밋 SHA/변경 파일을 기록한다. 사용자가 코드/깃허브 수정을 금지한 에셋 검수 단계에서는 업로드하지 않고 추후 적용용으로 인계한다.

## 인계 프롬프트 자동 작성 규칙

- **ZIP의 실제 내부 내용을 먼저 열어 검사**한다. originals/, corrected/, frames/, previews/, metadata/, REVIEW_REPORT.md 등이 있으면 각 역할을 식별한다.
- 적용에 필요한 최종 PNG를 명시하되, 폴더명이나 파일명을 추측하지 않는다.
- 원본 시트와 개별 프레임 중 **앱 로더가 요구하는 형식**을 확인하게 한다. 시트의 이미지가 실제로 분리되어 있지 않다면 먼저 분리/검증하도록 지시한다.
- 검수용 GIF·원본·중간 산출물은 런타임에 임의로 복사하지 않는다. 원본은 보존한다.
- ZIP의 메타데이터가 있으면 프레임 순서·앵커·재생 시간을 우선 확인한다. 없으면 사용 중인 앱 코드와 이미지 자체에서 근거를 구해 결정하게 한다.
- 기존 저장소의 버전/브랜치/미커밋 변경과 설정·다른 행동을 보호한다.
- 사용자 요청에 맞게 **코드 적용 / 자산 교체 / 검수만 / 기획만** 범위를 명시한다.
- 수정 후 자동 테스트, 실제 Windows 시각 확인이 필요한 항목, 실패 시 롤백 방식을 적는다.
- **실기기 검수가 끝나기 전에는 이를 완료했다고 주장하지 않는다**. 검수까지 끝난 작업만 문서화 후 GitHub에 커밋·푸시한다.
- 인계 프롬프트는 ZIP 제작자에게 생성 책임이 있으며, 사용자가 매번 별도 요청하지 않아도 결과와 함께 제시한다.

## 복사용 최종 인계 프롬프트 템플릿

아래 대괄호는 **납품한 실제 파일에서 확인한 사실만** 채운다. 확인되지 않은 정보는 `미확인 — 검사 필요`로 표시한다.

```text
# Avatar Living in Desktop — 검수 에셋 인계 및 프로그램 적용

GitHub: https://github.com/kospher123-sys/avata_LIVINGinDESKTOP.git

첨부 ZIP:
- [실제 ZIP 파일명 1 — 캐릭터 모션 / 이펙트 / 통합 에셋]
- [실제 ZIP 파일명 2 — 필요한 경우]

에셋 설명:
- 기술/동작: [실제 명칭]
- 구간 및 프레임 수: [ZIP에서 확인한 실제 목록]
- 최종 사용 대상: [확인된 파일 및 폴더]
- 보관/검수 전용: [originals, previews, review 등 실제 존재하는 항목]
- 검증 상태: [PASS/WARNING/FAIL/미검증 항목]
- 제약/주의사항: [좌표, 방향, 앵커, 타이밍, 합성 규칙 등 확인된 값]

진행 요구:
1. 현재 GitHub 저장소와 실행 중인 버전, 로컬 미커밋 변경을 조사하고 기존 기능을 보존해줘.
2. 첨부 ZIP을 안전하게 풀고 파일명·실제 PNG 개수·캔버스·RGBA 알파·손상 여부·메타데이터를 검사해줘.
3. 원본과 검수용 파일을 보존하고, **검수된 최종 적용용 이미지**만 선택해 기존 앱 로더가 요구하는 형식으로 매핑해줘.
4. 캐릭터 모션과 이펙트가 분리되어 있으면 독립 레이어로 유지하고, 방향·손 위치·바닥 앵커·재생 시간·구간 전환을 실제 코드에 맞춰 연결해줘.
5. 기존 동작(IDLE, WALK 및 이미 완료된 기술), 설정, 클릭 통과, 모니터·배율 동작을 회귀 테스트해줘.
6. 미리보기(밝은/어두운 배경, 실제 프레임 시간)와 자동 검증을 제공하고, 사용자 Windows 실기기 검수가 필요한 부분은 분리해서 알려줘.
7. 발견된 결함만 최소 수정하고, 검증 결과와 남은 문제를 보고해줘.
8. 검수까지 끝난 변경만 PROJECT_PLAN.md 등 관련 문서에 업데이트하고 GitHub에 커밋·푸시해줘. 미검증 부분은 완료로 기록하지 마.

최종 보고: 적용 파일 목록, 기존/신규 상태 비교, 테스트 결과, 사용자 확인 방법, GitHub 커밋 SHA, 남은 이슈.
```

## 실제 납품 응답의 권장 순서

1. 결과 ZIP 및 포함 내용
2. 검수 PASS / WARNING / 미검증
3. ZIP 안에서 런타임에 필요한 파일과 보관용 파일 구분
4. **복사해서 바로 쓰는 '다음 Work용 인계 프롬프트' 전문**
5. 후속 적용·실기기 확인 안내

## 적용 예시

AIR_BLAST라면 캐릭터 CHARGE / RELEASE / RECOVER와 별도 CAST / PROJECTILE / DISSIPATE / BACKDRAFT 효과를 구분한다. 단, 프레임 수/ZIP 구조/타이밍은 실제 납품 파일과 최신 확정 사양을 우선하며, 이전 계획 수치를 그대로 복사하지 않는다. 특히 변경된 AIR_BLAST v1.1의 손 앞 발사점, 전방 즉시 전개, 빠른 내부 흐름, 전방과 같은 방향의 후방 흡입은 실제 구현 전 검증이 필요한 사양이다.
