# AIR_BLAST v1.1 적용 및 검수 — 2026-11-11

## 문제 원인

조사 기준은 GitHub main의 089ed606a0983507e6553283998d26fb00d3f9ea다. v1.0은 캐릭터와 효과를 24장의 큰 PNG로 합성해 재생했다. PROJECTILE 중심이 손과 무관한 소스 캔버스 좌표에서 시작했고 프레임마다 작은 거리만 전진했다. 고정 캔버스 폭에 따라 공격 범위가 정해졌으며, BACKDRAFT는 작게 축소되어 실제 표시 길이가 짧았다.

원래 캐릭터 배율은 표시 키 / 606, 발 앵커는 원본 셀의 (288, 650)이다. 기본 오버레이 앵커 (148, 419)와 연결하고 좌우 반전도 이 발 위치를 기준으로 한다.

## 전방 렌더링

반복 타일만 사용하면 반복 경계가 드러나기 쉽다. 독립 스트릭만 배치하면 첫 발사 프레임의 전체 범위를 채우기 어렵다. 기본 기류를 전체 전방 범위에 반복하고, 더 작고 옅은 보조 기류가 다른 속도와 위상으로 흐르는 하이브리드 방식을 적용했다.

전방 원본의 세로 배율은 v1.0과 같은 표시 키 × 4 / 606이다. PROJECTILE의 공통 가시 영역 높이 131px는 표시 키 120px에서 약 103.76px다. 타일은 등비 확대·축소한다. 서로 다른 소스 프레임을 이웃 타일에 배치하고 일부를 겹친다.

기본 전방 속도는 표시 키의 초당 9배다. 표시 키 120px에서는 1080 논리 px/s이고 보조 기류는 그 1.7배다. 첫 발사 프레임부터 전체 범위에 타일이 존재하며 이후 위상과 PNG 프레임이 바뀐다.

## 손바닥과 화면 좌표

RELEASE 03은 두 손이 앞으로 펴진 자세다. 검수 메타데이터의 두 손 좌표 (445, 230), (470, 234)를 사용했다. 발사점은 앞쪽 손바닥의 x와 두 손 y의 평균에 소스 좌표 오프셋 (4, 0)을 더한 (474, 232)다.

화면 발사점은 실제 오버레이의 발 앵커에 (발사점 - 원본 발 앵커) × 표시 배율을 더한다. x 변위에는 방향을 곱한다. 실행 중 표시 키·방향·선택 화면을 바꾸면 다시 계산한다.

선택된 QScreen.availableGeometry()를 논리 좌표 QRectF로 변환하고 그 경계로 효과를 자른다. Windows 검사에서 발견된 QRect의 우측 포함 좌표와 QRectF의 끝 좌표 차이도 보정했다. 메인 기류는 손바닥 앞부터 발사 방향 작업 영역 끝까지다. 손이 화면 경계를 넘어선 경우 해당 방향 전방 폭은 0이다.

효과는 Always on Top, 입력 투명, 포커스 비활성 도구 창에서 그린다. 이 창은 작업 영역과 효과 띠의 교집합만 차지한다. 드래그 모드에서도 효과 창은 입력을 통과시킨다.

## 후방 기류

각 BACKDRAFT를 가시 윤곽으로 잘라 캐시한다. 표시 길이는 캐릭터 키의 80%이며 120px에서 96px다. 프레임별 가로 여백 때문에 실제 선이 작아지던 문제를 줄였다.

기류 위상은 캐릭터가 바라보는 전방으로 이동한다. 캐릭터의 현재 윤곽 바운딩 박스 뒤쪽에만 표시해 몸을 가로지르는 부분을 차단한다. 불투명도는 0.35다. CHARGE부터 전방 유지 구간이 끝날 때까지 뒤쪽 공기가 캐릭터 쪽으로 흘러든다.

회복과 효과 종료는 시간상 중첩된다. 캐릭터 12자세는 원래 순서로 재생하고 마지막 자세에서 효과가 끝날 때까지 기다린다. 기본 전방 재생은 1.2초, 전체 행동은 2초다. 전방 시간을 1.0~1.5초 안에서 늘리면 전체 행동의 마지막 유지 시간도 자동으로 늘어난다.

## Windows 실제 실행

Windows Qt 백엔드에서 우→좌→우 3회 재생했다. 매 회차 캐릭터 12자세를 모두 관측했고, 종료 후 원래 창 위치·크기와 IDLE을 확인했다. 양방향 첫 전방 paint는 각각 0.766초와 0.765초, 전체 캐릭터 프레임 07(RELEASE 03)에서 발생했다. 설계 발사 시점 뒤 5~6ms다.

실제 Windows 확장 스타일의 입력 투명·포커스 비활성을 확인했다. WindowFromPoint가 효과 창을 입력 대상으로 반환하지 않는 것도 검사했다. 작업 영역은 2560×1392, 배율은 1.0이었다. 전방은 오른쪽 x=2560, 왼쪽 x=0까지 계산됐다.

최종 측정에서 효과 그리기 371회, 평균 0.875ms, 95백분위 2.421ms였다. 타이머 간격 중앙값은 16.043ms, 95백분위는 17.206ms다. 세 번 재생 후 프로세스 작업 집합은 약 128.59/128.62/128.65MB였다. 해당 환경의 짧은 반복 검사 결과다. [Windows 측정 원자료](../previews/AIR_BLAST_v1.1/windows_runtime_metrics.json)

## 수정 파일과 조정

assets/characters/aang/air_blast_v11/effects.json의 palm_offset(원본 셀 px), speed_heights_per_second, backdraft_width_heights, flow_ms, fade_ms, density를 바꾸고 트레이의 이미지 다시 불러오기를 선택하면 반영된다.

- air_blast.py가 자산 검증, 화면 좌표, 타일·보조 기류, 입력 투명 효과 창을 담당한다.
- animation.py가 분리 효과 자산을 로딩하고 조정된 효과 시간만큼 마지막 자세를 유지한다.
- overlay.py가 발 위치·방향·화면 선택·숨김·중단과 효과 창을 연동한다.
- build_windows.py가 분리된 캐릭터·효과 PNG와 메타데이터를 패키징한다.
- main.py가 AIR_BLAST 패키지 검사, 독립 재생 검사와 --preview-air-blast를 제공한다.
- test_air_blast.py, test_air_trick.py가 좌표·시간·입력·폴백을 검사한다.
- preview_air_blast.py가 두 배경 GIF와 시간 추적 JSON을 만든다.
- extra_clips.json과 air_blast_v11/이 실행용 자산을 등록한다. README.md에는 실행과 조정 방법을 추가했다.

## 사용자 확인과 후속 개선

손과 바람의 연결감, 후방 흡입의 존재감, 체감 속도, 흰 배경 대비와 반복 무늬는 사용자 화면 검수가 필요하다. 여러 물리 모니터와 서로 다른 Windows 배율 조합은 좌표 자동 검사를 수행했으며 실제 다중 모니터 실험은 남아 있다.

6장의 PROJECTILE 위상을 반복하므로 넓은 화면에서 일부 반복성이 보일 수 있다. 사용자 검수에서 반복이 강하게 느껴지면 보조 기류 밀도·속도를 조정하거나 추가 기류 프레임을 검토할 수 있다.

배포 ZIP을 새 임시 폴더에 풀어 캐릭터 12장·효과 20장·CRC를 확인했다. 실행 파일의 패키지 검사와 독립된 Windows 재생 검사(--check-package --preview-air-blast)를 통과했다. 이 검사에서는 임시 설정과 별도 세션으로 12자세 전체, 첫 전방 paint의 RELEASE 03, 종료 후 IDLE과 효과 제거를 확인했다. [배포본 검사 원자료](../previews/AIR_BLAST_v1.1/package_check.json) 로컬 배포 파일은 dist/AangOverlay-AIR_BLAST-v1.1.zip이며 SHA-256은 f635244714a04e2987880dc132e033698dfb6694c3f092c9b4f257fe0f019339이다.
