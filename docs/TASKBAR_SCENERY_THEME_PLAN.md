# 작업표시줄·풍경 테마 개발 계획

> 기록일: 2026-11-11 (Asia/Seoul)
> 상태: 사용자 디자인 방향 합의 및 후속 개발 계획. 기능 구현·Windows 실기기 검증은 미착수.
> 통합 기획서: [PROJECT_PLAN.md](../PROJECT_PLAN.md)

## 사용자 요청과 합의

- 아앙이 걷는 바닥, 작품의 분위기를 참고한 풍경, 작업표시줄 바 자체를 함께 꾸민다.
- 여러 테마를 일정 간격으로 순서대로 전환하거나 실제 시간대에 맞춰 전환한다. 구체적 간격·시각은 미정이다.
- 바다·호수를 표현할 수 있게 하고, 건물도 테마와 함께 전환한다.
- 작업표시줄 위의 풍경뿐 아니라 아이콘·시계 뒤의 바 재질까지 꾸미는 것이 핵심이다.
- 바탕화면 아이콘, 실제 작업표시줄 아이콘·시계, 일반 프로그램 창은 배경 건물보다 앞에 표시되어야 한다. 배경은 입력·포커스를 방해하지 않는다.
- 사용자가 배경화면을 바꿀 때마다 합성 이미지를 수동 제작하지 않도록 한다.
- 캐릭터의 기존 표시 정책과 배경 표시 정책은 분리한다.

## 시안과 사용자 피드백

| 테마 | 풍경·바닥 | 바 자체의 재질 | 피드백 |
| --- | --- | --- | --- |
| 공기의 사원 | 구름 낀 산, 정자, 나무, 수평 돌길 | 낡은 돌벽·이끼·바람 문양 | 사용자 호평 |
| 바닷가 수정안 | 노을 바다, 해변 정자, 수평 모래길 | 모래·사암의 지층 단면, 조개 문양 | 수정 후 사용자 승인 |
| 물의 부족 | 달빛 호수/운하, 얼음 다리·건물, 얼음길 | 푸른 얼음 단면·물결 문양 | 사용자 호평 |

바닷가 초기안은 모래길 바로 아래 작업표시줄을 수중 이미지로 표현해 땅이 물 위에 뜬 듯 어색했다. 수정안에서는 바를 모래·사암 단면으로 바꾸고 바다는 걷는 길 뒤에만 배치했다. 이후 제작 시 초기 수중 바를 재사용하지 않는다.

생성 시안의 캐릭터·아이콘·시계는 배치 예시다. 실제 배포용 테마 이미지에는 포함하지 않는다. 캐릭터는 기존 승인 스프라이트, 아이콘·시계는 실제 Windows UI를 사용한다. 시안은 최종 투명 PNG/런타임 에셋으로 검수된 상태가 아니다.

## 이미지와 전환 설계

- 정적인 테마는 풍경·건물·바닥·바 재질을 하나의 긴 이미지로 제작 가능하다. 풍경 외부의 빈 영역은 실제 투명 알파로 만든다.
- 테마별 공통 보행 기준선과 바 영역 좌표를 메타데이터로 관리한다. 해상도·DPI·모니터·작업표시줄 높이에 맞춰 정렬한다.
- 하나의 원본 이미지를 쓰더라도 창 표시 순서상 필요하면 렌더링 영역/창은 분리한다. 단일 이미지가 단일 창을 뜻하지 않는다.
- 배경과 바를 같은 테마 ID로 묶어 함께 전환한다. 일정 간격 순환과 실제 시각 시간표는 구분한다.
- 절전 복귀·시계 변경 시 현재 시각에 맞는 테마를 재평가한다. 페이드 전환은 후속 선택 기능이다.
- 추후 독립적인 건물 교체·물결 애니메이션이 필요하면 해당 요소만 별도 레이어로 분리한다.

## 권장 구조와 기술적 미확정 사항

장기 방향은 기존 배경화면과 독립적인 바탕화면 배경 레이어다. 건물·풍경을 바탕화면 아이콘과 일반 창 뒤에 표시하고, 캐릭터 창은 별도로 유지한다. 기존 캐릭터의 항상 위 창에 풍경을 함께 그리지 않는다.

바탕화면 호스팅(예: WorkerW 계열)은 구현 후보이며 Windows 버전에 따른 호환성 검증이 필요하다. 단순히 최상단 속성을 끄거나 창을 맨 아래로 보내는 것만으로 안정적인 바탕화면 부착을 보장하지 않는다. 클릭 통과도 시각적인 표시 순서를 보장하지 않는다.

작업표시줄 재질에는 실제 작업표시줄 배경의 투명화가 필요하다. TranslucentTB는 검토 후보이며 설치·의존성 채택·자동 조작은 아직 결정하지 않았다. Windows 기본 투명 효과만으로 원하는 결과가 보장되는 것은 아니다.

특히 일반 창/최대화 창이 작업표시줄 뒤쪽까지 차지할 때, 투명 작업표시줄 아래에 테마 재질 대신 해당 창이 보일 수 있다. 바탕화면 뒤 레이어 한 장만으로 모든 창 상태에서 동일한 바 재질을 보장한다고 약속하지 않는다. 필요 시 바 재질 전용 창을 일반 창보다 앞·실제 작업표시줄보다 뒤에 두는 별도 구조를 검토하되 실제 동작으로 검증한다.

자동 배경화면 합성은 정적 첫 시험의 대안이다. 프로그램이 기존 배경에 자동 합성할 수 있으나 원본 보존·외부 배경 변경 감지·원상복구가 필요하다. 사용자가 매번 수동 합성하는 방식은 채택하지 않는다.

## 개발 순서와 완료 조건

1. 기존 동작 안정화 작업과 별도 기능으로 관리한다. 기존 AIR_BLAST 및 항상 위 표시 문제의 우선순위를 이 문서로 임의 변경하지 않는다.
2. 단일 모니터·정적 테마 하나로 바탕화면 배경 레이어 실험: 아이콘·일반 창 뒤 표시, 클릭 통과, 포커스 비점유, 바탕화면 보기 동작 확인.
3. 실제 작업표시줄 투명화 및 재질 표시 실험: 아이콘 클릭·검색·시작 메뉴·트레이·시계·미리보기 정상 작동, 일반/최대화 창에서도 재질 표시 결과 확인. 실패한 상태와 대체 구조를 기록한다.
4. 단일 이미지/영역 분리 여부를 확정한 뒤 세 테마를 런타임용으로 제작한다. 캐릭터 발 기준선, 알파, UI 가독성, 화면비를 검수한다.
5. 수동 선택과 배경·바·건물 동시 교체부터 구현하고 이후 시간표/순환·설정 저장을 추가한다.
6. DPI·해상도 변경, 작업표시줄 자동 숨김, 모니터 변경, Explorer 재시작, 절전 복귀, 전체화면, 종료 시 원상복구를 검증한다. 실제 다중 모니터 검증이 불가능하면 미검증으로 남긴다.

완료 판정은 시안 생성과 구분한다. 현재 완료된 것은 대화 기반 디자인 방향과 개발 계획 기록이다. 실제 표시 순서·작업표시줄 재질 유지·성능·Windows 호환성은 미검증이다.
