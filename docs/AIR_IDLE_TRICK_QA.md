# AIR_IDLE_TRICK 적용 검수

## 기준과 원본

- 기준은 GitHub main의 `da37e63`이다. v0.12의 실행 코드, 자동 둘러보기와 Windows 빌드 워크플로를 확인했다. 이후 WALK 시안과 AIR_IDLE_TRICK 검수 기록은 프로젝트 문서에 있었다.
- 입력 `AIR_IDLE_TRICK.zip` SHA-256은 `fae17b2898d4f81ed20a14f30091b73f67e3343a9469d32217e8f77b9aa8cfea`이다.
- ZIP 내부 29개 항목은 단일 루트 아래의 일반 파일이다. 상위 경로 참조, 절대 경로, 대소문자 무시 중복, 링크를 검사했고 CRC 검사를 통과했다. 전체 일괄 압축 해제 없이 검증한 항목만 읽었다.
- 구성은 캐릭터·바람·합성 PNG 각 6장, 대응 시트 3장, 120px 밝은색·어두운색 미리보기 2장, GIF 1개, 메타데이터·클립 JSON 2개, QA 문서, 원본 PNG 2장이다. 원본 PNG 두 장의 SHA-256은 ZIP의 메타데이터와 일치했다. 원본 ZIP과 이미지에는 쓰지 않았다.

## 이미지 판정

- 원본 2장은 2048×682 RGBA이며 알파가 전부 255다. 가공된 캐릭터·바람·합성은 모두 512×768 RGBA다. 바람은 첫·마지막 프레임에서 완전히 투명하고, 중간 네 프레임에는 반투명 효과가 있다. 캐릭터 위에 바람을 재합성한 결과가 ZIP의 합성 6장과 픽셀 단위로 일치했다. GIF도 같은 순서와 프레임 시간 160/150/160/220/180/170ms를 갖는다.
- 원본의 4번 바람은 y=11부터 시작해 기존 오버레이 좌표에서 상단을 넘는다. 앱에 복사한 바람 4번만 아래로 8px 이동해 알파 경계를 y=19로 맞췄다. 그 외 11개 적용 PNG는 ZIP 항목과 바이트 단위로 같다.
- 120px Windows 오버레이의 순차 캡처에서 준비, 팔 올림, 소용돌이, 회수 순서와 발 위치를 확인했다. 어두운 배경에서 효과를 구분할 수 있다. 밝은 배경에서 얇은 바람이 희미하고 기존 IDLE과 자세가 달라 진입·복귀 때 외형 변화가 보일 수 있다.

## 연결과 검증

- 별도 캐릭터·효과 폴더에서 번호가 일치하는 PNG를 읽고 프레임별로 한 번 합성해 캐시한다. 기존 렌더러의 공통 앵커와 좌우 반전을 사용한다. 클립 기준은 (256, 735), 서기 높이는 680이다.
- 자동·대기 모드에서 0.5초 이상 대기했고 20~40초 쿨다운이 끝났으면 단발 재생할 수 있다. 둘러보기와 휴식에 우선권을 준다. 트레이와 설정의 **공기 벤딩 한 번 보기**로 시작할 수 있다. 설정의 **확인 종료**, 드래그, 모드 변경, 휴식 진입은 동작을 중단한다. 일시정지·숨김은 진행을 멈추고 다시 시작할 때 이어서 재생한다. 필요한 PNG가 없거나 규격이 틀리면 클립을 비활성화하고 대기를 표시한다.
- v0.12 unittest 전체 49개 통과. Windows Qt 백엔드에서 신규 테스트 3개 통과. 실제 Windows 오버레이 타이머와 트레이 동작으로 120px의 6프레임을 순서대로 캡처하고 IDLE 복귀를 확인했다.
- Windows 폴더형 실행 파일 빌드 성공. 배포 폴더에 캐릭터·바람 PNG 12장이 모두 포함됐다.
