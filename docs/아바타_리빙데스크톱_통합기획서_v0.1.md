## 02 · 사용자 경험

사용자가 컴퓨터를 켜면 캐릭터는 자동으로 자신의 생활을 이어간다. 사람의 조작을 요구하거나 알림을 자주 보내지 않는다. 원하는 순간에만 캐릭터를 선택하여 기술을 사용하거나 위치를 바꿀 수 있다. 작업을 방해하지 않으며, 숨김/정지가 간단해야 한다.

- 장면 예시: 아앙은 공중에 떠다니고, 주코는 수련하며, 토프는 잠들고, 카타라는 상황에 반응한다.
- 원소 충돌은 화면에 수증기, 먼지, 바람에 휘날리는 불꽃 같은 반응으로 표현한다.
- 프로그램을 껐다 켜도 위치·생활 설정·최근 사건의 간단한 기록을 복원한다.

## 03 · 시각 디자인 및 이미지 제작

영화의 성장한 캐릭터 외형, 얼굴·의상·색상·헤어스타일, 손그림 2D 액션 및 원소 연출을 시각 기준으로 설정한다. 이전 TV 시리즈의 아동기 외형과 혼용하지 않는다. 원작 비율/세미 SD 두 가지 시안을 비교한 뒤 캐릭터 도감(character bible)을 고정한다.

| 비교 | 원작 비율 | 세미 SD |
| --- | --- | --- |
| 영화 속 모습 충실도 | 높음 | 기준 요소를 유지해야 함 |
| 작은 화면 식별성 | 실루엣과 크기에 영향 | 유리한 편 |
| 애니메이션 제작 | 세부 묘사와 일관성 부담 큼 | 복잡도 감소 가능 |
| 권장 | 기준 시안 필수 | 대체 시안 제작 및 결정 보류 |

- 제작 자산: 캐릭터별 정면/측면 기준도, 표정 시트, 색상표, 대기·이동·휴식·수련·밴딩 스프라이트, 원소 효과, 배경화면.
- 기본 방향: 좌우 두 방향, 투명 PNG/스프라이트 시트, 기준 발 위치(anchor), 동일한 초당 프레임 기준과 파일명 규칙.
- 기술/연출은 캐릭터 그림과 이펙트 스프라이트를 별도 레이어에 배치하여 추가·교체 가능하게 한다.
저작권: 공식 영화 스틸·영상·음원과 캐릭터 디자인은 권리자의 권리가 적용될 수 있다. 개인적 참고용 디자인과 공개 배포/판매는 구분한다. 공개 배포 시 사용 허락·라이선스 및 상표 이슈를 별도로 검토한다.


## 04 · 시간대별 생활 시스템

세계 시간(WorldClock)은 현실 시간과 독립된 데이터로 유지한다. AI는 시스템 시각을 직접 읽지 않고 WorldClock의 시간대·요일·장면 정보만 소비한다. 이를 통해 시간 모드를 바꿔도 AI 코드 수정이 필요 없도록 한다.

| 모드 | 동작 | 예시 |
| --- | --- | --- |
| 실시간 연동 | PC 시각 그대로 사용 | 현실 오후 8시 = 세계 오후 8시 |
| 가속/압축 | 설정 배율 또는 하루 길이에 따라 진행 | 세계 하루=30분/2시간/6시간 |
| 고정 | 특정 시간 유지 | 늘 해질녘 |
| 수동 | 사용자가 시각을 직접 이동 | 아침→밤 바로 변경 |
| 선택 옵션 | 일시정지, 시간대별 행동 강도, 밤 활동 제한 | 야간에는 조용한 행동 위주 |

- 설정 예: time_mode=accelerated, virtual_day_minutes=120, start_hour=15, paused=false, night_quiet=true.
- 시간이 변경될 때 기존 동작을 강제 중단하기보다 안전한 종료 지점에서 다음 행동을 선택한다.
- 시간대 예시: 아침-기상·스트레칭, 낮-이동·수련, 저녁-교류·휴식, 밤-명상·수면. 성격에 따라 편차를 허용한다.

## 05 · 캐릭터 AI 구조

각 캐릭터는 고유한 ActorState(위치/방향/행동/에너지/기분), Personality(성향 가중치), Memory(최근 사건), Relationship(타 캐릭터와의 관계)를 가진다. 감지→가능 행동 생성→점수 평가→행동 선택→애니메이션 실행 단계를 반복한다.

| 캐릭터 | 행동 성향 초안 |
| --- | --- |
| 아앙 | 호기심, 이동, 장난, 공중 동작, 중재 |
| 카타라 | 관찰, 물 수련, 방어, 동료 배려 |
| 주코 | 집중 수련, 명상, 대련, 도전 |
| 토프 | 휴식, 장난, 바위 조작, 대련 |

Utility 점수 예: score(train) = personality.train_weight + current_motivation − fatigue_penalty + context_bonus. 행동에는 cooldown, 이동 가능 범위, 타 캐릭터 동의 및 중단 정책을 둔다. 상호작용은 양쪽 AI가 동일 사건 ID를 공유해 모순을 막는다.

기억은 초기에는 사건별 짧은 기록(상대, 행위, 시각, 결과)만 저장한다. 성장치/레벨/스킬 잠금 해제는 없다. 기억은 행동의 다양성을 높이되, 영구적으로 성격을 크게 변화시키지 않는다.


## 06 · 밴딩·원소 반응 시스템

기술 엔진은 캐릭터 AI와 독립. 기술은 데이터 정의(skill_id, element, animation, cast_time, cooldown, range, projectile, effect, tags)와 공통 실행기(skill_executor)로 분리한다. 신규 기술은 정의 파일 + 필요한 애니메이션·이펙트만 추가하는 형태를 목표로 한다. 예외적인 기술 효과는 플러그인형 핸들러로 확장한다.

| 원소 조합 | 연출 예시 |
| --- | --- |
| 물×불 | 수증기 |
| 물×흙 | 진흙/젖은 바위 |
| 공기×불 | 불꽃 방향 변경·확산 |
| 공기×흙 | 먼지구름 |
| 물×공기 | 물안개·비산 |
| 불×흙 | 달궈진 바위·파편 |

충돌 처리: 이펙트의 hitbox가 겹치면 원소 태그를 비교하고 reaction_registry에서 반응을 검색한다. 단순 시각 효과부터 도입하여 복잡한 연속 물리 계산은 초기 범위에서 제외한다. 자동 수련·대련과 사용자 직접 시전은 동일한 SkillExecutor를 공유한다.

예시 기술 정의 (구조안): {"id":"water_whip","element":"water","animation":"katara_water_whip","cooldown_s":8,"tags":["projectile","water"]}


## 07 · 데스크톱/오버레이 (별도 상세 설계 예정)

본 단계에서는 요구만 확정하고 기술 구현 방식은 미확정: (1) 바탕화면에서 캐릭터 표시, (2) 필요 시 다른 앱 위에 표시, (3) 클릭 통과와 선택 모드 전환, (4) 전체화면 앱·작업 방해 회피, (5) 숨김 단축키, (6) DPI·다중 모니터 대응.

주의: 투명한 항상 위 창과 바탕화면 아이콘 뒤에 표시하는 창은 동일한 문제가 아니다. Windows Explorer 바탕화면 영역 배치는 Win32 연동 검증이 필요한 별도 기술 과제로 분리한다. 클릭 통과가 켜진 동안 캐릭터 직접 클릭은 불가능하므로 일시적 상호작용 모드나 별도 UI 설계가 필요하다.


## 08 · 소프트웨어 아키텍처

권장 초기 스택: Python 3, PySide6/Qt, Win32 API 연동(필요 영역), PNG 스프라이트, JSON 설정/기술 데이터. 장기적으로 렌더러를 교체할 수 있도록 코어 모델을 UI와 분리한다.

계층: App Controller → WorldClock + EventBus + WorldState → Character Agents → Action Scheduler → SkillExecutor/ReactionRegistry → Renderer + Desktop Adapter → Settings/Save Repository.

설계 원칙: 데이터 중심(Content/Data Driven), 이벤트 기반, AI Tick과 렌더 Tick 분리, 자산/로직 분리, 캐릭터와 기술의 안정적인 고유 ID, 무리한 글로벌 싱글톤 지양.


## 09 · 비기능 요구사항 및 목표

- 일상 작업의 방해 최소화: 클릭 통과, 화면 가림 제한, 즉시 숨김, 음소거 기본값.
- 초기 실험 목표: 4인 동시 표시, 애니메이션 약 30 FPS; AI 의사결정 2~5 Hz. 성능 수치는 프로토타입 벤치마크 후 확정.
- 전원·자원 절약: 화면 비활성/최소화/전체화면 앱 감지 시 프레임과 업데이트 빈도 감소 옵션.
- 안정성: 설정 파일 손상 복구, 로그, 일시정지/재시작, 종료 시 상태 저장.
- 개인정보: 기본 오프라인 동작, 활성 창 감지는 앱 종류·모드 구분에 필요한 최소 정보만 수집.

## 12 · 주요 위험과 결정 대기 항목

- 미결정: 영화 원작 비율과 세미 SD 가운데 최종 캐릭터 그림체. 우선 기준 시안 비교.
- 미결정: 배경화면 자체를 프로그램에서 변경할지, 독립적인 장면 배경을 표시할지.
- 미결정: 데스크톱 아이콘과 캐릭터 레이어 관계 및 작업창 위로 이동하는 조건. 오버레이 설계 문서에서 별도로 결정.
- 미결정: 캐릭터가 화면 가장자리에만 머무를지, 창 경계·바탕화면 바닥을 따라 이동할지.
- 위험: 원작 시각 자산의 권리 및 공개 배포의 제약.
- 위험: 대량의 프레임 제작·캐릭터 외형 일관성 유지. 초기에 1명/3동작 수직 슬라이스로 검증.
- 위험: Windows 업데이트·다중 모니터·전체화면 앱과의 충돌. 오버레이 프로토타입에서 조기 검증.
